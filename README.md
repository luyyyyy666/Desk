# desk 一体化中学辅助学习agent

desk 是帮助学生“学会一个知识点”的学习 Agent。学生提出问题或完成一道题，Agent 根据可信知识资料进行讲解、识别需要巩固的知识点、安排少量练习，再用新的作答验证学习效果。

**第一版只完成一个可验证的学习闭环：提问 → 引导 → 作答 → 反馈 → 针对性练习 → 查看进步。** 当前仓库处于需求与设计阶段，尚无可运行应用。

## 1. 首版目标与范围

产品长期面向中学学习，首版学科范围为**高中数学**，覆盖集合与逻辑、函数与导数、三角函数、数列、向量与复数、不等式、立体几何、解析几何、概率统计与计数等主要模块。学生可以按模块或知识点提问、诊断和练习。

内容按模块分批建设，首版发布时各主要模块均须有经过审核的代表性讲解、题目和完整学习路径；不要求一次穷尽所有题型与教材版本。页面展示已支持知识点，资料不足时明确提示，不把模型通用回答当作已验证的课程覆盖。

| 首版包含 | 交付边界 |
| --- | --- |
| 学习对话 | 文本提问、多轮引导、可信资料引用、明确下一步行动 |
| 小型知识库与题库 | 维护者手工录入/结构化导入，审核后用于答疑与练习；保留来源、知识点与版本 |
| 诊断与练习 | 冷启动用少量诊断题；按有效作答推荐每组 1–3 道审核题，可换一道 |
| 答题反馈 | 单选、可确定判分的数值题；文字过程用于辅导，不作为自动判分依据 |
| 错题与学习记录 | 保存作答、提示/解析使用、订正和相关知识点，可回看与再练 |
| 简单学习状态 | 展示知识点“证据不足、待巩固、巩固中、初步掌握”及支持该结论的具体作答 |
| 最小维护入口 | 教师/内容维护者管理资料和题目、审核版本、分配简单练习任务、查看授权学生的任务结果 |
| 交付终端 | 响应式网页，支持桌面和手机浏览器；单个试点空间、一种部署方式 |

首版不提供正式考试、成绩册或学业成绩认证。练习结果是学习反馈，不是学校正式成绩。

## 2. 使用流程

### 学生学习

1. 登录后进入学习页，选择待完成任务，或直接输入“我不会判断函数极值”等问题。
2. Agent 检索已审核资料，给出简短讲解和可点击依据；缺少有效作答时，邀请学生完成一道诊断题。
3. 学生提交答案，服务端按题目版本和确定性规则判分。Agent 结合判分结果解释原因，给出提示或解析。
4. 系统推荐 1–3 道相关审核题，并说明“为什么练这些题”；学生可接受、换题或暂停。
5. 学生完成新的同类题后，更新知识点学习状态。页面展示具体进步和下一步建议，也允许回看错题。

首页围绕“继续任务、开始提问、下一步练习”组织。学习对话与题卡位于同一工作区，错题和学习记录作为辅助入口，不建设复杂仪表盘。

### 教师或内容维护者准备任务

维护资料与题目 → 校正答案、解析和知识点 → 审核可用版本 → 按知识点/题目选择一组练习 → 分配给授权学生 → 查看提交与待巩固知识点。

任务只是有固定题目快照的练习集合，不需要试卷排版、总分排名、考试时间控制或三套组卷界面。教师与学生使用同一个网页应用，不新增独立管理系统。

## 3. Agent 如何工作

首版采用**单 Agent、有限工具、明确状态、可追溯结果**的结构。Agent 根据当前问题和学习状态决定是否查资料、取题或解释结果，业务服务校验其操作后执行。

```text
学生消息 / 已确认的答题结果
  → 加载本人会话与学习记录
  → 模型提出回答或工具请求
  → 服务端校验权限、参数和调用预算
  → 执行工具并返回结构化结果
  → 模型生成引导与练习建议
  → 保存消息、引用和执行状态
  → 学生继续作答或结束本轮
```

### 工具与职责

| 工具 | 作用 | 边界 |
| --- | --- | --- |
| `search_knowledge` | 查询已审核知识片段与来源 | 仅返回当前试点范围内允许访问的资料 |
| `get_learning_state` | 读取本人知识点状态和作答证据摘要 | 学生身份来自会话，模型不能指定其他学生 |
| `recommend_questions` | 按知识点、难度及已做题筛选 1–3 道题 | 只使用已审核有效版本；返回缺题原因，不生成伪造题目 ID |
| `get_question_help` | 获取当前题目的分级提示或解析 | 根据提交、请求和披露状态返回；使用帮助会记录为学习证据属性 |

题目审核、任务分配、提交答案、判分和更新学习记录是受控业务操作，不向模型开放任意写入工具。工具提供结构化 schema 和统一错误；没有浏览器、Shell、任意 HTTP 或跨 Agent 委派能力。

每轮调用有次数、超时及输出预算，支持取消与失败重试。工具结果和上传内容不能改变系统规则。具体状态与恢复要求见阶段目标。

### 引导与学习判断

- 默认先给提示和问题引导；学生明确查看解析时允许学习性讲解，并记录该题使用过帮助。
- 学生说“我懂了”、模型判断“已经掌握”、看过解析后答对原题，都不能单独证明掌握。使用新的同类题和独立作答作为证据。
- 无资料、资料不足或题库不匹配时明确说明，提供支持范围内可选行动，不能伪造引用或悄悄放宽约束。
- 学习状态采用可解释规则，展示样本数量与最近有效作答；首版不使用 BKT、三层长期记忆或完整知识图谱。

## 4. 最小技术架构

| 部分 | 方案 | 职责 |
| --- | --- | --- |
| 网页 | TypeScript + React | 学习对话、题卡、记录和简易维护入口 |
| 业务服务 | Go + Gin + GORM | 身份、权限、会话/运行编排、工具执行、题目审核、任务、判分和数据事务 |
| AI 服务 | Python + FastAPI | 内网模型适配、提示构建、结构化回答/工具意图生成 |
| 数据库 | MySQL/InnoDB | 用户、资料、题目版本、会话、作答和学习状态的权威记录 |
| 模型 | OpenAI 兼容接口，默认 DeepSeek | 经 Python 服务调用，模型和预算通过配置管理 |
| 部署 | 单套 Docker Compose | 网页、Go、Python 和 MySQL，在单个试点环境运行 |

Go 是唯一对外业务 API；Python 不直接写权威业务数据，也不直接执行有副作用的工具。Go 完成 Agent 循环与工具校验，Python 每次返回最终回答或结构化工具意图，避免两侧重复实现运行循环。

首版知识检索采用 MySQL 中的知识点筛选与关键词匹配，先保证小规模内容可检索和来源可定位；按固定评测集验证召回。只有实际召回不足时再引入向量检索。

首版不依赖 Redis/asynq、MinIO、Chroma/Qdrant、OCR、图数据库或 Agent 框架。内容以表单或小批量 JSON 导入为主，统一字段和版本；不建设通用文档解析和文件存储流水线。

## 5. 数据与可信边界

- 最小实体包含 `user`、`student_assignment`（维护者与学生授权关系）、`knowledge_entry`、`question_version`、`task`、`task_item`、`task_recipient`、`session`、`agent_run`、`message`、`attempt`、`knowledge_state`。按实际设计合并关联表，不为规划能力创建空表。
- 单个试点空间设置学生和维护者两类角色，账号由维护者开通；学生只访问本人数据，维护者仅查看被授权学生的任务结果。会话采用服务端可撤销凭据，网页使用安全 Cookie 并校验 CSRF/Origin，不预设多租户权限引擎。
- 资料/题目按“草稿 → 已审核 → 已下架”管理，内容修改产生新草稿；任务与作答引用固定题目版本。被下架题不产生新练习；保留已提交记录以便复盘。
- 答题由 Go 按已审核答案和确定性规则判分，不把模型输出当作权威对错。不能确定的答案显示“暂不能自动判断”，不进入掌握度计算。
- 提交使用幂等键，作答与学习状态在同一 MySQL 事务中更新；重复请求不新增有效证据，更正后按有效作答重算。首版不引入分布式成绩回流和 outbox。
- 会话只保存必要消息、运行状态及最近相关记录，不建立跨应用长期记忆。每次恢复重新校验身份、资料状态及版本；中断运行不能展示为完成。
- 审核、判分、引用访问及工具授权均由服务端约束。日志不含模型密钥、会话凭据或学生完整对话，开发验证使用虚构数据。

## 6. 首版完成标准

| 编号 | 可验收行为 |
| --- | --- |
| V1-01 | 各高中数学主要模块均有可用讲解与练习，维护者可以准备、审核并分配；草稿、下架题和无效版本不能进入新的学习任务 |
| V1-02 | Agent 可检索、引用、分步引导并调用有限工具；引用可打开到正确资料，信息不足时明确降级 |
| V1-03 | 学生可以提交、获取确定性反馈、订正与回看；重复提交或重试不会重复累计作答证据 |
| V1-04 | 提交后获得针对性练习与理由；独立同类题验证效果，提示/解析辅助作答不会冒充独立掌握 |
| V1-05 | 学生不能访问他人记录或维护功能；模型不能越权修改题目、任务和判分，引用/工具遵守同一权限 |
| V1-06 | 每轮有有限预算与超时；取消、失败、刷新和重复请求可恢复到真实状态，不无限调用或重复生成业务结果 |
| V1-07 | 从干净环境部署后可完成一条完整学习流程；网页在桌面及手机浏览器可用，运行说明与配置真实可执行 |

验收样本、质量目标和异常用例见 [首版阶段目标](docs/stage-goals.md)。开发过程中记录实际验证结果，不把指标当作已经达成的能力。

## 7. 后续扩展

以下能力不作为首版开发或发布条件：语文/英语及其他学科、小程序、拍照 OCR 与多格式文档解析、复杂组卷和 PDF 输出、正式考试/主观题成绩确认、个人库与校本库完整共享、班级/年级分析、家长报告、勋章积分、SIS、BKT、三层长期记忆、完整知识图谱、多 Agent、向量检索和多租户/私有部署组合。

先根据首版试点中的反馈准确性、练习完成率和学习效果决定扩展顺序。行为风险分与监考不属于当前学习 Agent 的发展重点。
