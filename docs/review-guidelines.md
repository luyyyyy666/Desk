# desk 工程 Review 规范

配合 [README](../README.md)、[首版阶段目标](stage-goals.md) 和 [开发规范](../AGENTS.md) 使用。首版是面向高中数学的单 Agent 学习工具，评审围绕 V1-01–V1-07，不要求未进入首版的考试、家校、OCR、小程序或复杂画像能力。

当前仓库处于文档阶段。区分需求、已实现行为和实测结果；建议布局、脚本和质量目标不能冒充已运行事实。

## 七个通用机制

### 1. 明确行为约束

说明在什么条件下应该或不应该发生什么，并对应用户要求、当前首版需求或接口语义。例如“提示后答对被显示为掌握”的问题，应定位为“辅助作答不能作为独立掌握证据”。个人技术偏好和后续规划不是阻塞理由。

### 2. 建立因果链

沿“用户操作 → Go 身份/运行/工具校验 → MySQL 或 Python 模型 → 结果保存 → 页面/下一次练习”查找第一个错误决定。PR 根因描述是待验证假设，不能从页面现象直接跳到局部过滤。文档改动沿需求、阶段、技术和验收检查一致性。

### 3. 确认责任层与事实来源

Go 拥有授权、运行循环、工具执行、判分和事务，MySQL 是业务事实来源，Python 生成回答或工具意图。模型文本、会话摘要、前端状态不能替代题目版本、独立作答标记和学习记录。修复优先落在拥有完整信息的责任层。

### 4. 检查现有机制再新增

搜索相邻状态和调用点，说明现有机制不足在哪里、新旧边界如何划分。避免新增平行权限、工具循环、题目状态或学习规则。尚无代码时建立最小机制，不为未来需求引入框架、队列和独立服务。

### 5. 检查相关生命周期

检查请求、持久化、工具结果、页面展示、刷新、取消、重启和重试。关注迟到响应覆盖终态、同消息多次运行、帮助已显示却未记录、题目下架继续提交、重复证据以及证据失效后的重算。只检查相关风险，不机械穷举全部系统。

### 6. 保持完整且聚焦的范围

每处改动应由同一行为约束解释。可独立发布/回滚的无关问题拆开；同一跨层契约不拆成短暂失效的半套修复。首版简化不能省略对象权限、内容审核、版本、幂等及真实状态，也不能偷偷恢复完整教育管理平台范围。

### 7. 用行为证据验证

缺陷尽量给出修改前复现、修改后通过及关键反例。数据库约束、事务和并发用隔离真实 MySQL；Mock 工具只证明协议，不证明模型质量。纯文档检查链接、表格、范围与术语，不创建逐字复述实现的测试。未验证范围明确说明。

### Prompt 与工具调用

- 上下文只包含当前权限允许的资料和相关学习记录；用户消息、资料及工具文本不能覆盖系统规则。
- 工具白名单和 schema 由 Go 执行，模型输出先验证；不开放 Shell、浏览器、任意网络或跨 Agent 能力。
- 题卡在提交/明确求助前不返回答案；查看提示/解析与针对题目的 AI 帮助必须标记。检查侧面询问同题答案或换会话后重做是否被误计独立证据。
- `get_question_help` 的帮助记录是幂等副作用，其他三个工具只读；取消后不可覆盖终态，提交时重新核验帮助使用状态。不要用“工具主要只读”忽略证据写入。
- Go 和 Python 不重复运行循环；重试不绕过总预算，超时结果未知不伪装完成，重启明确标记中断。
- 固定评测记录模型/提示版本、样本、依据和结果；按阶段目标分别报告正常质量、异常边界、延迟和失败率，不以文本流畅代替准确性。

### 学习证据

“初步掌握”是有限样本下的规则状态，不是成绩或长期能力认证。检查独立题目 ID 而不仅是版本 ID；辅助作答、未判定答案和无效证据不能进入独立窗口。查看解析后的原题订正有学习价值，但不能增加独立成功数量。

规则与状态以阶段目标为准。修改窗口、阈值、辅助标记或判分时同步规则版本、更正回算和验收样例；不得只改 UI 标签。维护者纠错保留原提交并使受影响证据失效，不伪造学生答案。

## 需要重新分析的信号

只改提示词/页面却留下服务端错误决定；模型或客户端反推身份/版本；同一规则多处猜测；新机制与已有抽象重叠；测试只检查 helper 而未证明学习结果；新增多端/多租户/分布式设施却不能对应首版目标。遇到这些信号先分析证据，不自动增加审批或停止已授权工作。

## 提交说明与评审输出

简单修改说明问题、结果和验证即可；复杂修改回答预期约束、现象与复现、因果链、权威责任模块、既有机制、影响范围、验证和未验证边界。相关 schema、模型或部署变更补充兼容与恢复方式。

开始评审记录分支/PR、基线 SHA、当前 SHA 和工作区范围。新提交出现后，旧结论不自动覆盖新版本，按影响补审。发现优先，按实际影响使用 P0–P3；每条写出路径与行号、触发条件、受破坏约束、后果和责任层修复方向。风格建议与可证实缺陷分开，不因文件数或个人框架偏好阻塞。

```text
评审对象：基线 SHA、当前 SHA、是否包含工作区改动

发现
1. [P1] 标题
   证据：路径:行号与触发条件
   约束：应保证的行为及需求依据
   后果：实际影响范围
   方向：应修复的责任模块

验证
- 已执行的命令、路径和结果
- 未验证的边界与环境限制
```

没有可证实缺陷时说明“未发现阻塞问题”及验证范围，不称产品已全部验收。单独 Review 默认只读；向 GitHub 发 review/评论、批准或合并需要相应用户授权。用户同时要求修改推送时完成已授权动作，不重复索取授权；必要验证失败、CI 未完成或 PR 仍为 Draft 时不宣称可合并。
