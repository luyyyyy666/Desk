# desk 首版阶段目标

首版目标是交付一个可用的单 Agent 学习闭环，范围以 [README](../README.md) 为准。首版覆盖高中数学各主要模块，内容按模块分批建设；当前全部阶段为**待开发、待验收**。按依赖逐阶段验证，周期根据工作量评估。

## 阶段总览

| 阶段 | 目标 | 主要交付 | 完成标准 |
| --- | --- | --- | --- |
| S0 | 准备可信内容与基础入口 | 账号、内容审核、题目版本、最小任务与网页框架 | V1-01、V1-05 基础路径 |
| S1 | 跑通标准 Agent 循环 | 对话、工具、引用、预算、失败与恢复 | V1-02、V1-05、V1-06 |
| S2 | 跑通学习闭环 | 判分、证据、简单状态、错题与同类练习 | V1-03、V1-04 |
| S3 | 完成试点验证 | 质量评测、端到端验收、单套部署与修复 | V1-01–V1-07 全部通过 |

## S0 可信内容与基础入口

**阶段目标：**学生能登录并获得一份有正确答案、可追溯版本的学习任务，维护者能准备可靠内容。

- 仅设学生与维护者两类角色。维护者手工开通账号并配置学生授权关系；学生只能读取本人会话、作答和任务，维护者只访问授权学生任务结果，不默认读取私人聊天。
- 建立 README 所列高中数学主要模块及知识点字典；题目标签仅要求学科、单元、主知识点、题型和固定难度。每题一个主知识点用于首版统计。
- 资料以文本和公式录入，字段包含标题、内容、知识点、出处及可定位片段；题目包含题干、选项或数值答案、解析、提示、判分规则和版本。支持同一 schema 的小批量 JSON 导入，错误项逐条报告并由维护者修正。
- 审核状态为草稿、已审核、已下架；编辑审核内容产生新草稿。资料和题目只有审核后才能供学生使用。维护者可以审核自己录入的内容，首版不建设多级审批。
- 按知识点或手选题目形成简单练习任务，分配给授权学生。任务保存题目版本快照，不含考试总分、排名、计时或复杂排版。
- 页面包括登录、学习工作区、学习记录和内容/任务维护入口。维护者与学生共用 React 应用，手机浏览器可访问。

**首版内容基线：**README 所列 9 个主要模块各选择至少 2 个代表性知识点，每个知识点至少 4 道审核题，其中至少 3 道可用于独立同类题验证；准备对应讲解片段和提示。起步规模至少为 18 个知识点、72 道题，覆盖清单显示模块、知识点、支持题型和审核状态。可按模块分批联调，发布前补齐各模块代表性路径，不将单元演示称为高中数学覆盖。此基线不意味着完整教材和所有题型已覆盖；数学正确性须人工检查，不能以未审核内容凑数。

**完成标准：**V1-01 和 V1-05 的资源/任务权限路径通过；无效内容不能导入为已审核，题目修改不污染任务快照。首个可运行模块补充真实安装、启动、迁移和验证说明。

## S1 标准 Agent 与有依据的辅导

**前置依赖：**S0 的账号、知识片段和题目版本可用；先用固定学习状态及确定性推荐规则接通工具，S2 再接实际证据。

### 运行协议

Go 持有 `agent_run`、身份、预算和工具执行权，Python 通过内部 HTTP 完成一次模型调用，返回 `final` 或 `tool_calls`。模型输出经 schema 校验，Go 执行允许的工具并将结构化结果送入下一轮。首版自行实现有界循环即可，不引入多 Agent 或通用工作流编排框架。

- 运行状态：`queued → running → completed / failed / cancelled / interrupted`；终态不能被迟到响应覆盖。取消停止新工具调用并尽力取消当前模型请求，界面不得把部分文本当作已完成答复。
- 每个会话同一时刻最多一个运行；重复消息请求使用幂等键返回已有运行，相同键不同载荷返回冲突。并发状态通过 MySQL 原子条件更新控制，不依赖单进程内存锁。
- 默认每轮最多 4 次模型请求、6 次工具执行、60 秒总时限；模型输入和输出预算配置化，所有重试计入预算。超时、参数不合法和达到上限时结束并说明原因，保留可恢复记录。
- 浏览器刷新查询已有运行；服务重启后将失去执行者的运行标记为中断，通过显式重试创建新运行并关联前次记录，不声称续接了已丢失的模型执行。
- 首版采用受理请求返回 `run_id`、查询状态与最终回复的方式；不要求 token 流式输出。错误包含 `code/message/trace_id`，不能暴露内部错误或密钥。

### 四个工具

| 工具 | 输入与输出 | 校验 |
| --- | --- | --- |
| `search_knowledge` | 查询文本、允许的知识点；返回片段 ID、内容、版本与引用位置 | Go 限定已审核试点资料，返回前再次校验有效状态 |
| `get_learning_state` | 可选知识点；返回本人状态、有效样本及证据摘要 | 身份由运行上下文绑定，不接受模型指定 student_id |
| `recommend_questions` | 知识点、难度、数量；返回候选题卡和推荐理由 | 数量 1–3、版本有效、排除近期已做题；无题返回缺口 |
| `get_question_help` | 当前题目版本、提示级别/解析请求；返回允许的帮助 | Go 验证该题与当前会话/任务关系及明确用户请求，并记录帮助披露 |

前三个工具只读取；`get_question_help` 涉及的帮助记录采用 `(run_id, tool_call_id)` 幂等写入，提交时仍由服务端重新汇总，模型不能把辅助标记改回独立作答。工具参数不能申请审核、正式考试、修改判分或任意网络/文件操作。

### 对话与答案披露

默认先做简短讲解或给提示；学生明确选择“查看解析”时允许展示已审核解析。无需模拟正式考试禁答体系，但推荐题卡在提交或请求帮助前不返回标准答案。提交后可查看反馈，所有后续原题重做均不作为新独立证据。

会话保存必要历史，模型上下文采用最近消息和按知识点查询的学习摘要，不建设长期三层记忆。历史或资料中的指令不能改变工具权限。没有资料时不伪造引用；超范围问题解释支持边界，并引导回已支持知识点。

**完成标准：**V1-02、V1-05 和 V1-06 通过。记录合法工具、非法工具、越权参数、循环超限、超时、取消、刷新、重启与重复请求的结果。

## S2 练习反馈与学习闭环

**前置依赖：**S1 工具与运行协议可用，S0 有足够的同类题。

### 作答与确定性判分

首版支持单选和维护者配置的确定性数值题：单选匹配选项 ID；数值按题目规则解析规范化十进制/分数及显式容差。拒绝任意表达式执行，无法可靠解析时标记“暂不能自动判断”，不判错、不更新学习状态。一般代数等价证明、自由解答过程和作文评分不在首版范围。

学生提交走 Go API，不能通过对话消息或模型工具伪造有效作答。记录学生、题目版本、答案、服务端时间、帮助标记和结果；使用唯一约束和幂等键，作答与学习状态更新在同一事务中完成。重复请求不重复累计；同一学生同一题目的版本变动或重复练习不能冒充新的独立题目。

题目下架后禁止继续产生新作答，并提示换题；已有提交保留快照。维护者发现错误答案时可将受影响证据标为无效并重算，不直接伪造学生提交。错题订正另存，不覆盖原答卷。

### 简单学习状态

按主知识点统计最近最多 3 道不同题目的首次有效、未使用帮助的作答。后续是否看解析不改变已经保存的首次独立结果；提交前使用提示、解析、AI 针对该题的讲解则标记为辅助作答。针对当前题目的 AI 讲解即使未走帮助工具，Go 也须在返回内容前保守标记为辅助作答；标记按学生与题目关联，跨会话重做不能重置。无法确认是否使用帮助时不作为独立证据。

| 状态 | 首版规则 |
| --- | --- |
| 证据不足 | 最近窗口少于 2 道独立题；出现错误时可以推荐巩固，但不下掌握结论 |
| 待巩固 | 至少 2 道独立题且至少一道答错，之后尚未开始针对性再练 |
| 巩固中 | 已有待巩固证据且开始再次训练，或最近结果尚不足以满足初步掌握条件 |
| 初步掌握 | 至少 2 道不同独立题，最近最多 3 道均正确；显示样本量与时间，不宣称长期稳定掌握 |

规则作为首版可配置基线，状态持久化时记录规则版本。先判断是否达到初步掌握，再按样本数量、错误和再练记录判断其余状态；新错误可使状态回退。无数据与辅助练习不得折算为零分或独立成功。更正或证据失效后按有效记录重算。

### 推荐与闭环

- 无历史数据时按所选知识点推荐一道诊断题；学生自述薄弱只作为训练意向。
- 根据有效错题的主知识点优先推荐基础/同级题，每组 1–3 道，说明目标及来自哪条证据。学生可换题、暂停或稍后继续，接受练习后再由业务 API 保存固定题目版本。
- 推荐采用标签过滤与简单排序；无满足条件的审核题返回缺口，不用模型临时编题代替。目标知识点、题型和难度约束的调整由用户明确选择。
- 独立同类题用于验证效果，原题订正和辅助作答用于学习过程展示。学生能查看任务进度、错题、知识点状态和对应作答，维护者可看授权任务的完成及待巩固点。

**完成标准：**V1-03、V1-04 通过。覆盖完整学习路径、重复提交、并发提交、辅助作答、同题重做、数值格式异常、缺题、证据失效与重算。

## S3 试点质量与交付

**前置依赖：**S0–S2 的实际功能完成，数据库和模型配置可用。单套 Compose 部署网页、Go、Python、MySQL；不建设多租户平台或双部署体系。

### 首版质量与交互目标

| 项目 | 目标与测量口径 |
| --- | --- |
| 内容正确性 | 首批审核题的标准答案、提示和解析全部人工校验；单选与数值判分固定样例结果全部正确 |
| 伴学质量 | 固定至少 27 个支持范围内用例，9 个主要模块各至少 3 个；至少 90% 回答经人工判定为正确且有帮助，并单列各模块结果，关键结论有真实相关依据。引用无伪造、定位与权限正确；不要求每步计算机械加引用 |
| 异常与边界 | 另设至少 10 个资料不足、超范围、提示注入、越权及故障用例；相应拒绝/降级/恢复符合预期，不混入正常质量分母 |
| 确定性反馈 | 在声明的试点环境、10 个并发学习会话下，提交判分与规则推荐 P95 ≤2 秒；模型讲解异步生成，不阻塞已确定结果保存 |
| Agent 交互 | 同环境下普通成功对话完成 P95 ≤20 秒；总时限 60 秒，计入全部调用和重试。注明模型与网络条件，超时/失败单列，不从指标中隐去 |
| 数据与权限 | 重复提交不重复证据；跨学生访问、未授权维护操作和模型越权全部拒绝；引用与帮助标记校验一致 |
| 可部署与恢复 | 干净环境按文档启动，刷新和重启后数据可查；备份恢复 MySQL 后完成学习路径；桌面及手机浏览器验证题卡/公式/错误状态 |

这些是首版试点验收目标，不是已完成的测试结果。记录环境、版本、模型、样本、步骤、实际结果和未验证范围；未达标时修复或明确调整目标后复验，不能虚报通过。

### 发布检查

V1-01–V1-07 对应 README 中全部首版验收，须逐项提供证据。最终演示：维护者分配练习 → 学生遇到问题 → Agent 检索提示 → 学生提交 → 判分与错因解释 → 同类题训练 → 独立验证 → 查看学习状态与证据。

提供真实的安装/构建、配置示例、迁移、初始化虚构账号、运行、检查、备份恢复和停止服务说明。模型密钥不提交到仓库，Mock 结果不能冒充真实模型质量或真实部署验收。

## 后续能力的进入条件

首版以外功能仅进入路线规划，不创建实现任务或验收阻塞。先观察试点中的题目覆盖、反馈准确性、完成率与重复使用，再决定深化高中数学知识点和题型、扩展其他学科、OCR、小程序、教师高级任务、家校、正式考试、画像模型或外部集成。每次扩展应单独明确范围、依赖和验收，不自动恢复为完整学校管理平台。
